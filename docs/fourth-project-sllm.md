# 4차 프로젝트: 긴 추천 입력과 입력 길이 안내

브랜치: `feat/sllm`

## 반영 내용

- 추천 자유 입력·설문 답변·Q&A 입력은 앞뒤 공백 제외 1~10,000자로 검증한다.
- 현재 Streamlit 입력창을 여러 줄로 바꾸고 최소/최대 길이를 표시한다.
- 추가 선택값은 기본적으로 미선택(`null`)이다. 미선택 값은 원문의 추출 조건을
  덮어쓰지 않으며, 사용자가 직접 선택한 값만 우선 적용한다.
- 사용 목적만 있는 짧은 요청도 추천 대상이다. 모든 선택 조건을 입력할 필요는 없다.
  목적 자체가 없거나 불명확한 경우는 기존처럼 확인 질문을 반환한다.
- CLI·서비스에 길이가 잘못된 입력을 직접 전달해도 예외 종료 대신
  `needs_clarification` 응답으로 입력 길이를 안내한다.
- 새 frontend에서도 `src/contracts/input_limits.py`와 같은 길이 정책을 적용해야 한다.
- 조건에 `additional_use_cases`, `additional_tasks`, `ethernet_required`,
  `min_camera_connectors`, `min_display_outputs`, `unverified_requirements`를 추가했다.
- 추가 용도·작업은 선호 점수에 반영한다. 주 용도는 기존 검수 정책을 따른다.
  지원이 검수되지 않은 추가 용도는 후보의 확인 필요 사항에 표시한다.
- 유선 LAN과 최소 연결 수는 카탈로그의 실제 사양으로 필터링한다.
- 예산·소음·전력 등 검증되지 않는 요구는 후보의 확인 필요 사항으로 보존한다.
- 보유 제품·예시 제품을 추천 대상 제한으로 오해하지 않도록 추출 지침을 보완했다.
- 조건 JSON 출력 예산은 512에서 2,048토큰으로 늘렸다. 입력과 출력이 모델의
  문맥 한도를 넘으면 원문을 자르지 않고 오류를 반환한다.

## 호환성과 검증 범위

기존 1.1.0 조건 입력을 계속 수용하기 위해 추가 필드는 기본값을 가진다.
출력에는 새 필드가 포함되므로 엄격한 이전 클라이언트는 함께 배포된
`docs/schemas/condition.schema.json`과 `chat-response.schema.json`으로 갱신해야 한다.
새 frontend 구현 자체는 이번 변경에 포함하지 않는다.

기존 폼의 명시적인 `true`/`false` 호출은 그대로 지원한다. 새 frontend에서도
미선택(`null`)과 명시적인 아니요(`false`)를 구분해야 한다.

자동 테스트는 긴 원문 보존, 입력 길이 경계, 조건 필터 및 점수, 확인 필요 표시와
기존 계약·서비스 회귀를 검증한다. 실제 Qwen/LoRA 추출 정확도나 GPU 성능을
검증한 결과는 아니다. 기존 adapter는 새 필드를 학습하지 않았으므로 긴 입력,
끝부분 정정, 복수 목적, 희망/필수 조건을 포함한 holdout 평가 후 필요하면 재학습한다.

## 2026-09-10 검증

- 최신 `origin/main`과 작업 시작 커밋은 `ee05e57ddaf74aae77c16d9451db01c1254dc742`로
  동일하며, 원격 main과의 병합 충돌은 없다.
- 변경 후 전체 테스트: **267 passed, 1 skipped**. Windows의 symlink 생성 권한이
  필요한 기존 테스트 1건을 건너뛰었다.
- 같은 로컬 manifest를 사용한 변경 전 기준 코드: **242 passed, 1 skipped**.
  기존 테스트 242건을 유지하면서 입력·호환성 회귀 테스트 25건을 추가했다.
- 이전 조건 JSON의 새 필드 기본값, 기존 명시적 폼 선택 우선순위, 미선택 값 보존,
  목적만 있는 홈 서버·카메라·스마트팜·코딩 교육 추천을 검증했다.
- 실제 Streamlit AppTest로 두 화면의 안내 문구·최대 길이, 짧은/긴 요청의
  추가 선택 없는 제출, 빈 입력의 서비스 호출 차단을 확인했다.
- Chrome에서 제품 추천·Q&A의 여러 줄 입력과 **최소 1자 / 최대 10,000자** 안내를
  직접 확인했다. 추천 화면의 추가 조건 6개는 모두 `선택 안 함`으로 표시된다.
- 로컬 공식 문서 manifest(18문서·270청크), 실제 catalog, BM25 검색,
  템플릿 답변 생성기로 짧은 홈 서버/카메라 요청과 긴 복합 요청을 점검했다.
  세 요청 모두 `answered`, 제품 카드 1개, 출처 8개를 반환했다.
  이 통합 점검의 **조건 추출은 고정값 대역**이며 모델 정확도 측정이 아니다.
- 실행용 manifest는 3차 프로젝트의 로컬 검증 자료를 복사해 사용했고 Git에
  포함하지 않았다. 재색인, 카탈로그 변경, 환경변수 추가는 필요하지 않다.
- 실제 Qwen/LoRA 평가는 사용자 요청에 따라 중단했다. 프롬프트의 동일 평가셋
  전후 모델 품질 비교는 이번 검증에서 제외하며, 품질 개선 수치를 주장하지 않는다.
